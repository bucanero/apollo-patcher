Have a PSP save?

The PSP encrypts saves itself, underneath whatever the game does. Unwrap that layer first — then the tools below, or the full patcher, can read what is inside. You will need the save’s PARAM.SFO as well as the file itself.

Have a PS3 save?

The PS3 encrypts saves itself too, listing what it protects in a file called PARAM.PFD — unwrap that layer first, and then the tools below, or the full patcher, can read what is inside. Bring that PARAM.PFD as well as the save file itself.

          Settings
          
      
          
        Which console Apollo writes saves for. Both are optional, and
        neither changes how a save is read — only what is written back.
      
          
    
          
  
          

  
          
    
          PSP — Fuse ID
          
    
          
      
    
          
    
          
      Savedata modes 4 and 6 derive two of a PARAM.SFO’s
      hashes from the console’s own fuse. A PSP loads a save whose values
      differ, so this is only needed to reproduce one console’s output
      byte for byte. Leave it blank for FFFFFFFFFFFFFFFF, which is
      what Apollo falls back to on a console too.
    
          
  
          

  
          
    
          PS3 — console ID (IDPS)
          
    
          
      
      
    
          
    
          
      Inside PARAM.PFD, one of PARAM.SFO’s four
      hashes is keyed by the IDPS of a single machine — that is what binds
      a save to a console. Name yours and the PS3 tool offers to re-bind a save
      to it; leave it blank and every save keeps the binding it arrived with,
      which is what patching one in place wants. The user number reaches only a
      trophy folder’s hashes.
    
          
    
          
      Re-binding is the PARAM.PFD half of moving a save. A save
      also carries account fields in its own PARAM.SFO, and those
      are not touched here.
